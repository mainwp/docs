You can move your MainWP Dashboard to another server while retaining its settings, clients, child site records, and Add-on data. Transfer the complete WordPress installation, including the database, installed Add-ons, uploads, and MainWP encryption-key files.

<Warning>
If the Dashboard domain or subdomain changes, exclude `wp_mainwp_wp` and `wp_mainwp_wp_sync` from search-replace, using your actual table prefix. Replacements that match child site URLs can corrupt those addresses. Include these tables in the backup and migration; exclude them only from search-replace.
</Warning>

For a new domain or subdomain, with or without a server change, follow [Move MainWP Dashboard to a New Domain or Subdomain](/advanced/changing-the-domain-of-your-mainwp-dashboard-site). That guide covers the complete workflow and URL recovery. The [Domain Changes During Migration](#domain-changes-during-migration) section below also includes the exclusion command.

## What You'll Learn

- How to prepare a complete Dashboard migration
- How to protect child site URLs if the Dashboard address changes
- How to verify retained data, Add-ons, and connections
- How to troubleshoot sites that fail to reconnect

For the underlying WordPress transfer process, see [Migrating WordPress](https://developer.wordpress.org/advanced-administration/upgrade/migrating/).

## Before Migration

### Document Your Setup

| Item | Why It Matters |
|------|----------------|
| Dashboard URL | Determines whether the move also requires a domain or subdomain change |
| Child site URLs | Lets you check that migration did not change their addresses |
| Add-ons and their settings | Lets you verify that installed Add-ons, templates, and schedules were retained |
| MainWP account and license access | Lets you reactivate Add-on licenses if needed |
| Scheduled work on the old server | Must stop on the old copy after the move to avoid duplicate activity |

Open **MainWP > Sites > Manage Sites** (`/wp-admin/admin.php?page=managesites`) and click **Sync** in the header before migration. You can [export your site list](/sites/how-can-i-export-child-sites) for comparison, but that export does not replace a full Dashboard backup.

### Create Backups

<Warning>
Create a fresh backup and verify that it completed with all required files and tables before starting migration. A database-only transfer does not preserve the entire Dashboard installation.
</Warning>

| Backup Type | Contents |
|-------------|----------|
| Database | Full Dashboard database, including all MainWP and Add-on tables |
| Files | Complete WordPress installation, including installed Add-ons and uploads |
| MainWP key files | Entire MainWP uploads directory, normally `wp-content/uploads/mainwp/`, including `pk`; preserve the corresponding directory if uploads are customized |
| Configuration | `wp-config.php`, applicable server rules, and any externally configured scheduled jobs |

The database holds settings and records. Add-on code and encryption-key files are stored on disk. Missing key files can prevent the migrated Dashboard from decrypting connection keys and other encrypted data.

### Preserve Native Backup Files

If you use [Native Backups](/sites/backups/manage-backups) in the MainWP 6.3 Release Candidate (RC), also back up and transfer the Dashboard's private backup directory. It is outside the WordPress installation, so copying WordPress files and uploads alone can leave these archives behind.

The default location is `mainwp-private/<wordpress-directory-name>/backups` beside the WordPress directory. Your hosting setup or a custom `MAINWP_BACKUP_PRIVATE_DIR` setting can change this location. Confirm the directory in use and include it in the transfer, keeping it outside publicly accessible folders.

Preserve the backup encryption keys and recovery passphrase. After the move, check **Snapshots & Restore** and any **Local Path** storage destinations to confirm that existing backups remain accessible before removing the old Dashboard.

## During Migration

Use a migration plugin, your host's migration service, or a manual transfer that copies the full database and files. Confirm that the destination meets the [MainWP Dashboard requirements](/advanced/miscellaneous/mainwp-system-requirements). Update the destination's database connection settings in `wp-config.php` if necessary.

Some migration tools perform automatic URL replacement during export, import, or restoration. If the Dashboard URL changes, confirm the search-replace exclusions before starting. Excluding tables from the backup or transfer would omit the MainWP records you need to retain.

Keep the original backup until verification is complete. After the move, use the destination as the active Dashboard and stop scheduled work on the old copy.

## Domain Changes During Migration

A move from `dash.example.com` to `mainwp.example.com` is a Dashboard URL change even though both addresses use the same parent domain.

<Warning>
Exclude `wp_mainwp_wp` and `wp_mainwp_wp_sync` from every domain search-replace, replacing `wp_` with your actual prefix. The exclusions protect child site records from matching replacements; the tables must still be migrated in full.
</Warning>

Run this preview against the restored Dashboard at the destination, substituting the full old and new Dashboard URLs and the actual table prefix:

```bash
wp search-replace \
  'https://dash.example.com' \
  'https://mainwp.example.com' \
  --skip-tables=wp_mainwp_wp,wp_mainwp_wp_sync \
  --skip-columns=guid \
  --dry-run
```

Review the reported tables and replacements. If they match the intended change, remove `--dry-run`:

```bash
wp search-replace \
  'https://dash.example.com' \
  'https://mainwp.example.com' \
  --skip-tables=wp_mainwp_wp,wp_mainwp_wp_sync \
  --skip-columns=guid
```

The example uses WP-CLI's default table selection. Have your host review additional tables before expanding the operation, and configure the same exclusions for any separate automatic replacement. See the [WP-CLI search-replace reference](https://developer.wordpress.org/cli/commands/search-replace/).

Corruption depends on the searched text matching a child site address. For example, replacing `example.com` with `example.net` also changes `client.example.com`, even when that child site has not moved. For host-assisted or manual URL changes, and repairs after an incorrect replacement, use the [domain and subdomain guide](/advanced/changing-the-domain-of-your-mainwp-dashboard-site#preventing-url-corruption).

## Keeping the Same Domain

If the complete Dashboard URL stays the same, a domain search-replace is not needed.

<Steps>
<Step title="Prepare the destination">
Restore the complete files and database, configure the server to serve the existing Dashboard domain, and verify its HTTPS certificate.
</Step>
<Step title="Update DNS">
Point the Dashboard domain to the destination server. Allow for DNS caching before assessing access from different locations.
</Step>
<Step title="Check network access">
If child site security rules restrict the Dashboard by server IP, update the relevant allowlists for the destination.
</Step>
<Step title="Verify connections">
Follow the checks below. A complete migration preserves the connection data, so reconnect only sites that report an error after syncing.
</Step>
</Steps>

## After Migration

### Verify Dashboard Access

<Steps>
<Step title="Log in at the destination">
Confirm that the Dashboard opens from the destination server and that settings, clients, and child site records are present.
</Step>
<Step title="Check server information">
Open **MainWP > Info > Server** (`/wp-admin/admin.php?page=ServerInformation`) and review any requirements or configuration warnings.
</Step>
<Step title="Verify Add-ons and their data">
Confirm that installed Add-ons are present and their settings were retained. For example, check your saved Pro Reports templates and schedules. A complete files-and-database migration does not require recreating this setup.
</Step>
</Steps>

### Reconnect Add-ons

Open **MainWP > Add-ons > Manage Add-ons** (`/wp-admin/admin.php?page=Extensions`) and check license activation. If licenses need reactivation at the new location, follow [Activate Add-ons](/dashboard/overview/manage-extensions#activate-add-ons). License activation and the presence of your saved Add-on data are separate checks.

### Verify Child Site Connections

<Steps>
<Step title="Open Manage Sites">
Go to **MainWP > Sites > Manage Sites** (`/wp-admin/admin.php?page=managesites`) and compare the child site URLs with your saved list.
</Step>
<Step title="Sync all sites">
Click **Sync** in the header and review the results. On a successful sync, MainWP Child updates its stored Dashboard address automatically if it has changed.
</Step>
<Step title="Test site access">
Use **Jump to WP Admin** on several child sites and confirm that their current data appears in the Updates view.
</Step>
</Steps>

### Reconnect Disconnected Sites

For a failed connection, check the child site's URL, MainWP Child activation, copied encryption-key files, and any firewall rules that restrict the new Dashboard server. If search-replace changed site addresses, follow [Fixing Corrupted Child Site URLs](/advanced/changing-the-domain-of-your-mainwp-dashboard-site#fixing-corrupted-child-site-urls).

After correcting the cause, use **Reconnect** in the affected site's action menu under **Sites > Manage Sites** (`/wp-admin/admin.php?page=managesites`). Supply the current [Unique Security ID](/getting-started/child-plugin-5-2-1-reconnecting-child-sites-with-unique-security-id) if requested.

MainWP Child has no editable Dashboard URL field, and a domain change does not require manually updating that address on every child site. For unresolved errors, see [Troubleshoot Connection Problems](/troubleshooting/potential-issues).

### Test Core Functionality

Verify the workflows you use, including sync, **Jump to WP Admin**, the Updates view, and Add-on settings. If you use scheduled reports or other scheduled actions, confirm that they are configured on the destination and no longer run from the old copy.

## Self-Check Checklist

- [ ] Complete files and database backup verified before migration
- [ ] MainWP and Add-on tables, files, and encryption-key files copied
- [ ] MainWP tables excluded from search-replace if the Dashboard URL changed
- [ ] Dashboard accessible from the destination server
- [ ] Settings, clients, child site records, and Add-on data retained
- [ ] Add-on licenses checked
- [ ] Child site URLs unchanged or repaired against the original list
- [ ] Sync and Jump to WP Admin checks successful
- [ ] Scheduled work runs only from the destination Dashboard
