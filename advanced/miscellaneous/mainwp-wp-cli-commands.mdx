MainWP includes WP-CLI integration for managing your MainWP Dashboard and configuring MainWP Child connection authentication from the command line. This enables automation, scripting, and advanced management workflows.

## What You'll Learn

- Available WP-CLI commands for site management
- How to sync, update, and manage sites via command line
- How to configure MainWP Child password authentication for a WordPress user
- Example automation scripts

## Prerequisites

- MainWP Dashboard v4.1.3 or later
- WP-CLI installed on your MainWP Dashboard server for `wp mainwp` commands
- WP-CLI available on the server hosting the child site for `wp mainwp-child` commands
- MainWP Child activated on the child site
- Child sites connected to your MainWP Dashboard for Dashboard-side management commands

For more information about WP-CLI, visit the [official WP-CLI documentation](https://wp-cli.org/).

## Built-In Help

WP-CLI lists every option for a command, including the ones that take a value such as `--site-url`, `--type`, `--slug`, `--ver` and `--ssl_verify`, with a short description and examples:

```bash
wp help mainwp sites
wp help mainwp site
wp help mainwp updates
```

<Note>
Running `wp mainwp sites` with no option prints a table of all child sites. The older `--list` and `--count` options still print the same table, but they are no longer listed in the help.
</Note>

    ## Sites Management

    Commands for managing multiple child sites simultaneously.

    ### List All Sites

    ```bash
    wp mainwp sites --all-sites
    ```

    Displays every child site in your MainWP installation.

    ### Count All Sites

    ```bash
    wp mainwp sites --all-sites-count
    ```

    Returns the total number of child sites.

    ### Connected Sites

    ```bash
    wp mainwp sites --connected-sites
    ```

    Lists only child sites with active connections.

    ### Connected Sites Count

    ```bash
    wp mainwp sites --connected-sites-count
    ```

    Returns count of actively connected child sites.

    ### Disconnected Sites

    ```bash
    wp mainwp sites --disconnected-sites
    ```

    Lists child sites that are currently disconnected.

    ### Disconnected Sites Count

    ```bash
    wp mainwp sites --disconnected-sites-count
    ```

    Returns count of disconnected child sites.

    ### Sync All Sites

    ```bash
    wp mainwp sites --sync-sites
    ```

    Synchronizes data across all child sites.

    ### Check All Sites

    ```bash
    wp mainwp sites --check-sites
    ```

    Verifies the status of all child sites.

    ### Disconnect Sites

    ```bash
    wp mainwp sites --disconnect-sites 2,5
    ```

    Disconnects the child sites with the given comma-separated IDs.

    If a site cannot be disconnected, the command prints a warning for that site and moves on to the next one. If any site failed, the command ends with `Disconnect completed with errors` and a non-zero exit code, so scripts can detect the failure.

    <Warning>
    Without site IDs, `--disconnect-sites` disconnects all of your child sites.
    </Warning>

  <Tab title="Site">
    ## Single Site Operations

    Commands for managing individual child sites. Replace `<id>` with the site ID.

    Every `wp mainwp site` command except `--add-site` needs a site ID. Without one, the command stops with `Empty site id.`

    ### Site Information

    ```bash
    wp mainwp site --site <id>
    ```

    Retrieves comprehensive data for a specific child site.

    ```bash
    wp mainwp site --site-info <id>
    ```

    Returns: site name, URL, WordPress version, PHP version, MainWP Child plugin version, PHP memory limit, MySQL version, active theme, and server IP address.

    ### Plugins

    ```bash
    wp mainwp site --site-installed-plugins <id>
    wp mainwp site --site-installed-plugins-count <id>
    wp mainwp site --site-active-plugins <id>
    wp mainwp site --site-active-plugins-count <id>
    wp mainwp site --site-inactive-plugins <id>
    wp mainwp site --site-inactive-plugins-count <id>
    wp mainwp site --site-abandoned-plugins <id>
    wp mainwp site --site-abandoned-plugins-count <id>
    ```

    ### Themes

    ```bash
    wp mainwp site --site-installed-themes <id>
    wp mainwp site --site-installed-themes-count <id>
    wp mainwp site --site-active-themes <id>
    wp mainwp site --site-inactive-themes <id>
    wp mainwp site --site-inactive-themes-count <id>
    wp mainwp site --site-abandoned-themes <id>
    wp mainwp site --site-abandoned-themes-count <id>
    ```

    ### Updates & Status

    ```bash
    wp mainwp site --site-available-updates <id>
    wp mainwp site --site-available-updates-count <id>
    wp mainwp site --site-http-status <id>
    wp mainwp site --site-health-score <id>
    wp mainwp site --site-security-issues <id>
    ```

    ### Site Management

    **Add a new site:**

    Use the administrator password when the Child Site requires Password Authentication:

    ```bash
    wp mainwp site --add-site --site-url=https://site.com --name=sitename --admin=adminuser --adminpassword='YOUR_ADMIN_PASSWORD'
    ```

    MainWP Dashboard 6.4 and later accepts `--adminpassword=<password>`. The flag must include a value. Password connections require HTTPS with certificate verification by default. Resolve certificate errors on the Child Site before retrying.

    If the Child Site requires a Unique Security ID, supply `--uniqueid`:

    ```bash
    wp mainwp site --add-site --site-url=https://site.com --name=sitename --admin=adminuser --uniqueid=YOUR_SECURITY_ID
    ```

    Supply both `--adminpassword` and `--uniqueid` when MainWP Child requires both methods. Avoid leaving connection credentials in shared scripts or shell history.

    **Sync, reconnect, disconnect, or remove:**

    ```bash
    wp mainwp site --sync-site <id>
    wp mainwp site --reconnect-site <id>
    wp mainwp site --disconnect-site <id>
    wp mainwp site --remove-site <id>
    ```

    ### Apply Updates

    ```bash
    wp mainwp site --site-update-wordpress <id>
    wp mainwp site --site-update-plugins <id>
    wp mainwp site --site-update-themes <id>
    wp mainwp site --site-update-translations <id>
    ```

    **Update a specific item:**

    ```bash
    wp mainwp site --site-update-item <id> --type=<plugin|theme> --slug=<slug>
    ```

    ### Plugin & Theme Control

    **Manage plugins:**

    ```bash
    wp mainwp site --site-manage-plugin <id> --action=<activate|deactivate|delete> --plugin=<plugin-slug>
    ```

    **Manage themes:**

    ```bash
    wp mainwp site --site-manage-theme <id> --action=<activate|deactivate|delete> --theme=<theme-slug>
    ```

    ### Check HTTP Status

    ```bash
    wp mainwp site --check-site-http-status <id>
    ```

    Verifies HTTP status of a child site.

  <Tab title="Updates">
    ## Updates Management

    Commands for controlling plugin and theme updates across sites.

    ### View Available Updates

    ```bash
    wp mainwp updates --available-updates
    ```

    Shows all pending updates across all child sites.

    ### Ignored Updates (Global)

    ```bash
    wp mainwp updates --ignored-plugins-updates
    wp mainwp updates --ignored-themes-updates
    ```

    Lists globally ignored plugin or theme updates.

    ### Ignored Updates (Per Site)

    ```bash
    wp mainwp updates --site-ignored-plugins-updates <id>
    wp mainwp updates --site-ignored-themes-updates <id>
    ```

    Lists ignored updates for a specific child site.

    `--site-ignored-plugins-updates`, `--site-ignored-themes-updates`, `--ignore-update` and `--unignore-update` need a site ID. Without one, the command stops with `Empty site id.`

    ### Ignore Updates Globally

    ```bash
    wp mainwp updates --ignore-updates --type=<plugin|theme> --slug=<slug> --name=<name>
    ```

    Globally ignores an update across all sites.

    ### Ignore Updates on Specific Site

    ```bash
    wp mainwp updates --ignore-update <id> --type=<plugin|theme> --slug=<slug> --name=<name>
    ```

    Ignores a specific update on one child site.

    ### Unignore Updates Globally

    ```bash
    wp mainwp updates --unignore-updates --type=<plugin|theme> --slug=<slug> [--ver=<version>]
    ```

    Reverses a global update ignore.

    ### Unignore Updates on Specific Site

    ```bash
    wp mainwp updates --unignore-update <id> --type=<plugin|theme> --slug=<slug> [--ver=<version>]
    ```

    Reverses a site-specific update ignore.

    ### Unignore Options

    | Option | Description |
    |--------|-------------|
    | `--type` | `plugin` or `theme` (required) |
    | `--slug` | Plugin file, such as `akismet/akismet.php`, or theme folder name (required) |
    | `--ver` | Version to unignore. Leave it out to unignore all versions. |

    Without `--ver`, the command unignores all versions, which is what `--ignore-updates` and `--ignore-update` store. A specific `--ver`, such as `--ver=5.3.1`, removes only that version from the ignored list and does not undo an ignore that covers all versions.

    `--ver` needs a value. The command refuses a bare `--ver`, an empty value or `0`, because those would otherwise unignore all versions on a site.

    ```bash
    # Remove the global ignore for all versions of Akismet
    wp mainwp updates --unignore-updates --type=plugin --slug=akismet/akismet.php

    # Unignore version 5.3.1 of Akismet on site 3
    wp mainwp updates --unignore-update 3 --type=plugin --slug=akismet/akismet.php --ver=5.3.1
    ```

  <Tab title="MainWP Child">
    ## MainWP Child Connection Authentication

    Run these commands from the child site's WordPress installation. The `settings` subcommand changes whether a specific WordPress user requires password authentication during the initial MainWP connection.

    The `settings` subcommand does not display current settings. Running `wp mainwp-child settings` without its required option returns an invalid arguments error.

    ### Disable Password Authentication

    ```bash
    wp mainwp-child settings --disable-pwd-auth <username> 1
    ```

    Replace `<username>` with an existing WordPress username.

    <Warning>
    Configure a [Unique Security ID](/advanced/miscellaneous/mainwp-connection-security#unique-security-id) at **WordPress Admin > Settings > MainWP Child > Settings** before disabling password authentication. The CLI command changes only the selected user's password-authentication setting; it does not generate a Unique Security ID.
    </Warning>

    ### Enable Password Authentication

    ```bash
    wp mainwp-child settings --disable-pwd-auth <username> 0
    ```

    <Note>
    The username is required. A final value of `1` disables password authentication, while `0` enables it. Omitting the final value defaults to disabling password authentication, so use an explicit value in scripts.
    </Note>

## Example Workflows

### Daily Sync Script

Create a script to sync all sites and check for updates:

```bash
#!/bin/bash
# daily-mainwp-sync.sh

# Sync all sites
wp mainwp sites --sync-sites

# Check for updates
wp mainwp updates --available-updates

# Check site status
wp mainwp sites --check-sites
```

### Get Site Overview

```bash
# Get all connected sites
wp mainwp sites --connected-sites

# For each site, get available updates
wp mainwp site --site-available-updates 1
wp mainwp site --site-available-updates 2
```

<Note>
Replace site IDs with your actual child site IDs. You can find site IDs by running `wp mainwp sites --all-sites`.
</Note>
