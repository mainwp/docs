The manual configurations below run `npx -y @mainwp/mcp` with your Dashboard URL, WordPress username, and [Application Password](/mcp-server/quickstart#before-you-start). Use them for another AI client or when you prefer a manual server connection.

If you keep credentials in a central `~/.config/mainwp-mcp/settings.json` instead (see [Configuration Reference](/mcp-server/reference/configuration#configuration-file)), omit the `env` block in any of these examples.

In MainWP Dashboard 6.3, open **AI > MainWP MCP** for [guided setup](/mcp-server/quickstart#guided-setup-in-mainwp-dashboard). The Application Password success dialog also offers a **Connect an AI tool** panel with prefilled Claude Code, Cursor, and VS Code configurations. Copy the format for your client while the password is visible; see [Application Passwords](/api-reference/rest-api/application-passwords#connect-an-ai-tool).

  <Tab title="Claude Code CLI">
    For the plugin, agent skill, and workflow commands, use [Install in Claude Code CLI](/mcp-server/claude-code-plugin#install-in-claude-code-cli). The commands below add only the MCP server manually.

    Add the server from your terminal:

    ```bash
    claude mcp add --transport stdio --scope user mainwp \
      --env MAINWP_URL=https://your-dashboard.com \
      --env MAINWP_USER=admin \
      --env MAINWP_APP_PASSWORD="xxxx xxxx xxxx xxxx xxxx xxxx" \
      -- npx -y @mainwp/mcp
    ```

    With a central settings file, the short form works:

    ```bash
    claude mcp add --transport stdio --scope user mainwp -- npx -y @mainwp/mcp
    ```

    User scope makes the server available across projects. The command contains the password and can remain in shell history. You can also define the same server in `~/.claude.json`.
  </Tab>

  <Tab title="Cursor">
    Add to `~/.cursor/mcp.json` globally. This configuration contains a password; keep it out of a shared project's `.cursor/mcp.json`:

    ```json
    {
      "mcpServers": {
        "mainwp": {
          "command": "npx",
          "args": ["-y", "@mainwp/mcp"],
          "env": {
            "MAINWP_URL": "https://your-dashboard.com",
            "MAINWP_USER": "admin",
            "MAINWP_APP_PASSWORD": "xxxx xxxx xxxx xxxx xxxx xxxx"
          }
        }
      }
    }
    ```

    Cursor also supports `${env:VAR_NAME}` placeholders if you prefer referencing system environment variables.
  </Tab>

  <Tab title="VS Code Copilot">

    ```json
            "MAINWP_USER": "admin",
            "MAINWP_APP_PASSWORD": "xxxx xxxx xxxx xxxx xxxx xxxx"
          }
        }
      }
    }
    ```

    VS Code can prompt for the password at runtime so it is never stored in the file:

    ```json
    {
      "inputs": [
        {
          "type": "promptString",
          "id": "mainwp_password",
          "description": "MainWP Application Password",
          "password": true
        }
      ],
      "servers": {
        "mainwp": {
          "type": "stdio",
          "command": "npx",
          "args": ["-y", "@mainwp/mcp"],
          "env": {
            "MAINWP_URL": "https://your-dashboard.com",
            "MAINWP_USER": "admin",
            "MAINWP_APP_PASSWORD": "${input:mainwp_password}"
          }
        }
      }
    }
    ```

## Managing multiple Dashboards

Give each Dashboard its own folder with its own `settings.json`, then point each server entry at the right folder with `cwd`:

```json
{
  "mcpServers": {
    "mainwp-production": {
      "command": "npx",
      "args": ["-y", "@mainwp/mcp"],
      "cwd": "/path/to/production-credentials"
    },
    "mainwp-staging": {
      "command": "npx",
      "args": ["-y", "@mainwp/mcp"],
      "cwd": "/path/to/staging-credentials"
    }
  }
}
```

The server reads `./settings.json` from its working directory first, so each entry picks up its own credentials. Details in the [Configuration Reference](/mcp-server/reference/configuration#configuration-file).
