The MainWP Dashboard Settings page controls how your Dashboard communicates with child sites, when automatic syncs and updates occur, how notifications are sent, and various performance optimizations. Understanding these settings helps you configure MainWP for your specific hosting environment and workflow requirements.

## What You'll Learn

- Configure sync timing and frequency
- Set up automatic updates for plugins, themes, and WordPress core
- Enable uptime and site health monitoring
- Manage email notification settings
- Configure built-in backups, Cost Tracker, Network Activity, and API Backups settings
- Optimize request settings for your hosting environment
- Access maintenance tools

## Prerequisites

- MainWP Dashboard installed and activated
- Administrator access to your Dashboard site
- At least one child site connected (for testing settings)

---

## Access Dashboard Settings

Open the **user menu in the top-right corner** of MainWP Dashboard and select **MainWP Settings** (`/wp-admin/admin.php?page=Settings`). The control displays your avatar or a user icon. **General Settings** opens by default; use the tabs on that page for the other settings areas.

  <Accordion title="General Settings" icon="gear" defaultOpen>
    **Page:** **top-right user menu > MainWP Settings > General Settings** (`/wp-admin/admin.php?page=Settings`)

    ### General Settings

    - **Daily sync time** (`H:mm`): Sets the start time of the first automatic synchronization run each day.
    - **Frequency of auto sync** (Default: Twice per day): Controls how many automatic sync runs happen per day (1 to 12).
    - **Timezone**: Defines the timezone context used for scheduled tasks and date/time displays in MainWP Dashboard.
    - **Date format**: Controls how dates are displayed across the dashboard interface.
    - **Time format**: Controls how times are displayed across the dashboard interface.
    - **Sidebar position** (Default: Right): Moves the sidebar or tag menu layout to the right or left side.
    - **Hide the Update Everything button**: Hides the `Update Everything` action from the Updates Overview widget.
    - **Show widgets**: Lets you choose which widgets are visible on Operations and individual site Operations pages.

    ### Updates Settings

    - **Plugin advanced automatic updates** (Default: Disabled): Enables automatic updates for trusted plugins.
    - **Theme advanced automatic updates** (Default: Disabled): Enables automatic updates for trusted themes.
    - **Translation advanced automatic updates** (Default: Disabled): Enables automatic updates for translation packages.
    - **WP Core advanced automatic updates** (Default: Disabled): Enables automatic WordPress core updates.
    - **Frequency of automatic updates** (Default: Daily): Sets whether automatic update runs execute daily, weekly, or monthly.
    - **Select day** (shown for `Weekly` or `Monthly`): Chooses the weekday or month day used by the automatic update schedule.
    - **Select time** (Default: `00:00`): Sets the time of day when automatic update runs begin.
    - **Advanced automatic updates delay** (Default: 1 day): Delays new updates for the selected number of days before auto-installing.
    - **Show WordPress language updates** (Default: Enabled): Shows translation updates in update management views.
    - **Update confirmations** (`Enable`, `Disable`, `Disable for single updates`): Controls confirmation prompts before update actions.
    - **Require a backup before an update** (Default: Disabled; shown when a primary backup system is available): Requires a recent backup before updates started from Manage Sites. Built-in backups accept completed full, database-only, or incremental backups.
    - **Days without of a full backup tolerance** (Default: 7): Sets the allowed backup age for the backup-before-update check.
    - **Require an offsite-verified backup** (Default: Disabled; built-in backups): Also requires verified copies on remote storage. Local Path destinations do not count as offsite storage. See [Backups Before Updates](/sites/backups/manage-backups#require-a-backup-before-updates).
    - **Abandoned plugins/themes tolerance** (Default: 365 days): Marks plugin and theme items as possibly abandoned if they have not been updated within the threshold.
    - **Abandoned check by local file date** (Default: Disabled; Dashboard 6.3): Uses the installed plugin's main file or theme's `style.css` modification date when WordPress.org has no usable last-updated date. It uses the same tolerance above. Sync the affected sites after changing it so MainWP Child 6.3 or later receives the setting. See [abandoned detection](/sites/updates/what-does-possibly-abandoned-mean#local-file-date-fallback-in-6-3) for its limits.

  </Accordion>

  <Accordion title="Advanced Settings" icon="sliders">
    **Page:** **top-right user menu > MainWP Settings > Advanced Settings** (`/wp-admin/admin.php?page=SettingsAdvanced`)

    Configure request, concurrency, caching, and connection settings to tune MainWP Dashboard performance and stability.

    MainWP syncs multiple child sites in parallel to speed up the process. The Maximum Simultaneous Sync Requests setting controls how many sites sync at once. Adjusting this value helps balance sync speed against server resources.

    ### Rate Limiting and Concurrency Controls

    | Setting | Default | Description |
    |---------|---------|-------------|
    | Global request limit | 4 | Total concurrent requests across child sites |
    | Minimum delay between requests in milliseconds | 200ms | Pause between consecutive requests |
    | Per-IP request limit | 1 | Concurrent requests to sites on the same server/IP |
    | Minimum delay between requests to the same IP in milliseconds | 1000ms | Pause between requests to the same server/IP |

    ### Child Request Timeout

    **Child request timeout (seconds)** controls how long MainWP Dashboard waits for a Child site request. In Dashboard 6.3, leave it blank to use the default of 72,000 seconds (20 hours), or enter a whole number of at least 300 seconds. Entering 72,000 clears the override. Invalid input keeps the saved value.

    Site removal uses 300 seconds by default; a saved timeout above 300 also raises that limit. This setting does not change a hosting provider's execution limits or guarantee a long-running request will finish.

    ### Batch Processing Settings

    | Setting | Default | Description |
    |---------|---------|-------------|
    | Maximum sites per batch | 10 | Number of sites processed per batch |
    | Delay between batches | 5ms | Pause between batches |

    ### Frontend Request Settings

    | Setting | Default | Description |
    |---------|---------|-------------|
    | Maximum simultaneous sync requests | 8 | Sites synced concurrently |
    | Maximum simultaneous install and update requests | 3 | Concurrent install/update operations |
    | Maximum simultaneous uptime monitoring requests | 10 | Concurrent uptime monitoring checks |

    ### Miscellaneous Settings

    - **Optimize data loading** (Default: Enabled): Uses synchronized plugin, theme, and user data for searches instead of fetching that data from child sites during each search.
    - **Auto-correct site URLs** (Default: Enabled): Automatically updates stored child site URLs for `www` differences and HTTP-to-HTTPS changes after verifying the corrected address. It does not automatically switch HTTPS to HTTP or change the domain, port, or path. Sites with **Lock site URL** enabled are not changed.
    - **Browser cache expiration time** (Default: 10 minutes): Sets how long browser-cached MainWP pages remain valid before refresh.
    - **Use WP Cron** (Default: Enabled): Controls whether MainWP registers and uses its WP-Cron jobs. Disable it only when those scheduled jobs will be triggered another way.
    - **Verify SSL certificate** (Default: Enabled): Verifies child site SSL certificates during connection attempts.
    - **Verify connection method** (Default: OpenSSL): Chooses between OpenSSL and PHPSecLib for connection verification.
    - **OpenSSL signature algorithm** (Default: `OPENSSL_ALGO_SHA256`): Selects the signing algorithm used with OpenSSL verification.
    - **Force IPv4** (Default: Disabled): Forces IPv4 for child site connections on hosts where IPv6 causes issues.
    - **Select data to sync**: Chooses which data sets are included in synchronization from MainWP Child sites.
    - **OpenSSL.cnf location** (conditional field): Lets you manually set OpenSSL config path when auto-detection is incorrect.

    Disabling **Auto-correct site URLs** stops background changes to stored addresses. Jump to WP Admin can still use the child-reported address for supported mismatches. To keep a particular site's stored address for both operations, enable [Lock site URL in that site's settings](/sites/management/manage-child-sites#lock-site-url).
  </Accordion>

  <Accordion title="Monitoring Settings" icon="heart-pulse">
    **Page:** **top-right user menu > MainWP Settings > Monitoring Settings** (`/wp-admin/admin.php?page=MonitoringSettings`)

    This page contains **Uptime Monitoring**, **Site Health Monitoring**, and post-update HTTP response checks.

    For full setup details, see [Uptime Monitoring](/sites/management/uptime-monitoring).

    ### Uptime Monitoring

    - **Enable Uptime Monitoring** (Default: Disabled): Enables or disables global uptime checks for child sites.
    - **Monitor Type** (`HTTP(s)`, `Ping`, `Keyword Monitoring`): Selects the uptime check method used for global monitors.
    - **Method** (HTTP-based monitoring): Chooses request method used when monitor type relies on HTTP checks.
    - **Keyword to look for** (Keyword Monitoring only): Sets the text that must be found in the response.
    - **Monitor Interval** (Default: 60 minutes): Sets how often uptime checks run.
    - **Timeout** (Default: 60 seconds): Sets maximum response time before a check is treated as failed.
    - **Down Confirmation Check** (Default: Enabled): Requires additional confirmation before flagging a site as down.
    - **Up HTTP Codes for HTTP Response and Uptime Monitoring**: Defines which status codes are treated as healthy.
    - **Attempt to bypass page cache** (Default: Disabled): Adds a best-effort cache-bypass request but does not guarantee that the check reaches the origin server.
    - **Monitoring Data Retention** (Default: 180 days): Controls automatic cleanup window for stored monitoring history.

    ### HTTP Response Check

    - **Check site HTTP response after update** (Default: Disabled): Runs a post-update HTTP check to verify the site still responds.
    - **Check site HTTP response method** (Default: `Head`): Selects whether that post-update check uses `Head` or `Get`.
    - Uses the same **Up HTTP Codes** selection as uptime monitoring for pass/fail evaluation.

    ### Site Health Monitoring

    - **Enable Site Health monitoring** (Default: Disabled): Enables or disables WordPress Site Health score checks.
    - **Site health threshold** (Default: `Should be improved`): Sets the threshold (`Should be improved` or `Good`) used to evaluate site health status.
  </Accordion>

  <Accordion title="Backup Settings" icon="hard-drive">
    **Page:** **top-right user menu > MainWP Settings > Backup Settings** (`/wp-admin/admin.php?page=BackupSettings`)

    Configure [MainWP Built-In Backups](/sites/backups/manage-backups) for connected Child Sites. These settings are available in the MainWP 6.4 Release Candidate (RC).

    - **Select primary backup system** (when other backup methods are available): Selects built-in backups or an integrated backup method.
    - **Built-in backups**: Enable backup creation, scheduling, and restores.
    - **On-demand backups to keep** (Default: 5; minimum: 1): Sets how many Back Up Now snapshots to keep per site.
    - **Encrypt backup archives**: Encrypts new backup archives before upload. Set and safely store a recovery passphrase first.
    - **Backup recovery passphrase**: Lets you recover the backup encryption key. Initial setup asks for your WordPress password; changes require the current passphrase.
    - **Backup run diagnostics**: Records detailed backup and restore progress locally. After enabling it and saving, use **Export diagnostics data** to download a report. See [Export Diagnostics](/sites/backups/manage-backups#export-diagnostics).
    - **Archive format**: Sets the global archive format; individual sites or tasks can override it.
    - **Auto detect maximum file descriptors on child sites**: Automatically detects how many files MainWP can open at once when creating a ZIP backup.
    - **Maximum file descriptors fallback value**: Provides a manual limit when automatic detection is unavailable.
    - **Load files in memory before zipping**: Reads files into memory before adding them to a ZIP archive.
    - **Send email when backup fails**: Enables backup failure emails.
    - **Send email when backup starts**: Enables backup start emails.
    - **Execute backup tasks in chunks**: Lets the scheduler work through multi-site backup tasks in smaller batches. This setting does not split backup archives into smaller files.

    For built-in backups, use **On-demand backups to keep** for Back Up Now and each task's **Backup Retention** settings for scheduled backups. Task retention applies separately to each Child Site. **Backups on server** and **Backups on remote storage** are legacy fields from the older backup system. See [Retention and Cleanup](/sites/backups/manage-backups#retention-and-cleanup) for their scope and the settings to use.

    For backup notification recipients and which failures trigger alerts, see [Backup Notification Emails](/sites/backups/manage-backups#backup-notification-emails).
  </Accordion>

  <Accordion title="Email Settings" icon="envelope">
    **Page:** **top-right user menu > MainWP Settings > Email Settings** (`/wp-admin/admin.php?page=SettingsEmail`)

    Configure global notification emails and edit per-notification templates.

    ![Email Settings page showing list of configurable email notifications](/images/dashboard/sites-management-c2490c.png)

    ### Manage Email Notifications

    - **Enable/Disable each notification**: Controls whether a specific notification type sends email.
    - **Recipients**: Defines destination addresses for each notification (multiple recipients supported).
    - **Subject and heading**: Lets you customize the email subject line and heading content per notification.
    - **HTML template management**: Lets you copy template files to uploads for customization or revert to default templates.

    ![Email notification settings form with recipient, subject, and template options](/images/dashboard/sites-management-7de353.png)

    ### Disable an Email Notification

    1. Go to **top-right user menu > MainWP Settings > Email Settings** (`/wp-admin/admin.php?page=SettingsEmail`).
    2. Click **Manage** beside the notification you want to disable.
    3. Turn the **Enable** toggle off and click **Save Settings**.

    Per-site overrides are available in child site edit screens under **Email Settings**, so site-specific recipients and behavior can differ from global defaults.

    **Auto Updates Email** summarizes successful automatic updates, grouped by child site. See [Automatic Update Summary Emails](/sites/updates/manage-updates#automatic-update-summary-emails) for timing and report contents.
  </Accordion>

  <Accordion title="Premium Updates" icon="arrows-rotate">
    **Page:** **top-right user menu > MainWP Settings > Premium Updates** (`/wp-admin/admin.php?page=PremiumUpdates`)

    MainWP Dashboard 6.2 automatically provides update compatibility for supported premium plugins and themes. Review **Detected Plugins** and **Detected Themes**, or use **Custom Identifiers** to add a product that needs additional compatibility or a renamed theme folder.

    Search installed products or enter a plugin's full `folder/main-file.php` identifier or a theme's installed folder, then click **Add New**. Existing compatibility filters still work. Vendor licensing requirements still apply on each child site.

    See [Premium Updates](/sites/updates/premium-updates) for the complete workflow, identifier formats, and detected-table details.
  </Accordion>

  <Accordion title="Cost Tracker Settings" icon="money-bill-wave">
    **Page:** **top-right user menu > MainWP Settings > Cost Tracker Settings** (`/wp-admin/admin.php?page=CostTrackerSettings`)

    This page configures cost tracking format and taxonomy data for the Cost Tracker module.

    ### Currency and Format

    - **Currency** (Default: `USD`): Sets the base currency used for tracked costs.
    - **Currency symbol position** (Default: `Left`): Controls whether the symbol appears on the left or right, with or without a space.
    - **Thousand separator** (Default: `,`): Sets the character used for thousands grouping.
    - **Decimal separator** (Default: `.`): Sets the character used to separate decimal values.
    - **Decimal places** (Default: `2`): Defines numeric precision used when displaying cost amounts.

    ### Cost Taxonomy Management

    - **Default product categories**: Lets you customize icon and color styling for built-in categories.
    - **Custom product categories**: Lets you add your own categories for classifying tracked products/services.
    - **Custom payment methods**: Lets you create reusable payment method labels for cost records.
  </Accordion>

  <Accordion title="Network Activity Settings" icon="timeline">
    **Page:** **top-right user menu > MainWP Settings > Network Activity Settings** (`/wp-admin/admin.php?page=SettingsInsights`)

    This module-based settings page controls logging used by both **Network Activity** and **Dashboard Insights**.

    ### Logging Controls

    - **Enable Network Activity logging** (Default: Enabled): Turns Network Activity and Dashboard Insights data collection on or off.
    - **Automatically archive logs**: Moves older log entries out of active logs into archived storage automatically.
    - **Data retention period** (Default: 3 years when archiving is used): Defines how long active logs are kept before auto-archiving.
    - **Retention period for Network Activity Logs on child sites** (Default: 7 days): Controls child-site cleanup separately from Dashboard log retention.
    - **Select events to log**: Lets you choose which dashboard and non-MainWP child-site events should produce log entries.

    <Note>
    Logged data is stored locally on your server and is not sent to MainWP servers.
    </Note>
  </Accordion>

  <Accordion title="API Backups Settings" icon="server">
    **Page:** **top-right user menu > MainWP Settings > API Backups Settings** (`/wp-admin/admin.php?page=SettingsApiBackups`)

    Connect your hosting provider's backup service through [API Backups](/sites/backups/api-backups).

    ### Provider Tabs

    - **Cloudways, GridPane, Vultr, Akamai (Linode), DigitalOcean, cPanel (WP Toolkit), Plesk (WP Toolkit), Kinsta**: Each tab enables API integration for that host/provider.
    - **Enable Provider API** toggles: Activates or deactivates each provider integration without removing saved credentials.
    - **Provider credentials**: Stores provider-specific authentication values such as API keys, account email/ID, URL, username/password, and site path fields where required.

    ### Per-Site Backup API Provider Settings

    - **Provider selection**: Defines which provider a child site backup mapping uses.
    - **Instance/environment selection**: Stores provider instance identifiers required to target the correct site/server context.
    - **Enable WP Toolkit API** (cPanel only): Activates the WP Toolkit API for the selected child site.
    - **Overwrite Global Settings** options (cPanel, Plesk, and Kinsta): Allows per-site credentials and connection details instead of shared global settings.
  </Accordion>

  <Accordion title="Tools" icon="wrench">
    **Page:** **top-right user menu > MainWP Tools** (`/wp-admin/admin.php?page=MainWPTools`)

    ![MainWP Tools section showing theme selection and various utility options](/images/dashboard/tools-page.png)

    ### Available Tools

    - **Select MainWP Dashboard theme**: Chooses the dashboard UI theme. Light and Dark are always available. With default Light/Dark and no custom theme files, the header uses direct sun/moon quick switching; otherwise the header opens the theme selection modal. Legacy options appear when currently selected, and custom `.css` files uploaded to the MainWP themes uploads directory are listed.
    - **Re-establish connections**: Forces MainWP Dashboard to reconnect with child sites. This destroys all sessions for the current MainWP connection user on each child site, so that account must sign in again.
    - **Reset OpenSSL key pair**: Generates a new OpenSSL key pair for child site communication.
    - **Start Quick Setup Wizard** (when available): Launches the MainWP onboarding wizard again.
    - **Export child sites**: Downloads accessible, non-staging child site data as a CSV file.
    - **Import child sites**: Opens the child-site import workflow.
    - **Disconnect all child sites**: Breaks all child connections while leaving MainWP Child active on those sites.
    - **Delete Add-ons API activation data**: Removes Add-ons activation metadata without deleting add-on settings.
    - **Delete archived Network Activity data**: Permanently removes archived activity logs.
    - **Restore all info messages**: Re-enables dismissed informational notices across MainWP Dashboard.
    - **Privacy and third-party service permissions**: Controls optional integrations for Usetiful guided tours, Chatbase support chat, and YouTube tutorial embeds.
  </Accordion>

## Self-Check Checklist

After configuring settings, verify:

- [ ] Automatic sync time is set to a low-traffic period
- [ ] Update confirmations match your workflow preference
- [ ] Email notifications are configured with correct recipients
- [ ] Request settings are appropriate for your hosting environment
- [ ] SSL verification is properly configured for your sites
