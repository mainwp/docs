MainWP Dashboard 6.3 registers 14 update management abilities into the WordPress Abilities API framework. These enable programmatic control over WordPress core, plugin, theme, and translation updates across your network.

## What You'll Learn

- Listing available updates across all sites
- Applying WordPress core, plugin, theme, and translation updates
- Managing ignored updates
- Batch update operations

---

## Confirmation and Update Holds in 6.3

`run-updates-v1`, `update-all-v1`, and the four `update-site-*` abilities require either `dry_run: true` to preview or `confirm: true` to execute. A call with neither returns `mainwp_confirmation_required` with HTTP 400. Do not set both flags to true.

Preview first, review the returned sites and update plan, then submit the same selection with `confirm: true`. A direct Abilities API request uses these flags; the separate one-time confirmation token used by MainWP MCP belongs to the MCP server's [confirmation flow](/mcp-server/safety).

Previews return `dry_run`, `would_affect`, `count`, `warnings`, and `errors`. Confirmed immediate responses include `dry_run: false`, `skipped`, and `summary.total_skipped`. Inspect both `errors` and `skipped`; a successful HTTP request does not mean every update was installed. Queued responses return a job ID for [status polling](/api-reference/abilities-api/batch-operations).

These abilities respect site-level and global update holds. Pending items blocked by a hold appear as skipped, and queued jobs recheck holds, site access, and the job owner's operation permissions when they execute. Translation updates also respect the site's translation ignore setting.

Adding an update hold remains available through the ignore abilities. Removing a site's own holds uses the new `mainwp/unignore-site-updates-v1` ability with preview or confirmation. The older `action: unignore` and `action: remove` paths return an error directing you to that ability.

## mainwp/list-updates-v1

List available updates across all sites.

**Method:** GET (readonly)

```bash
curl -u 'admin:xxxx' \
  'https://your-dashboard.com/wp-json/wp-abilities/v1/abilities/mainwp/list-updates-v1/run'
```

**Input Parameters:**

| Name | Type | Required | Default | Description |
|------|------|----------|---------|-------------|
| `site_ids_or_domains` | array | No | [] | Filter to specific sites |
| `types` | array | No | [] | Filter: `core`, `plugins`, `themes`, `translations` |
| `page` | integer | No | 1 | Page number |
| `per_page` | integer | No | 50 | Items per page (max 200) |

**Response:**

```json
{
  "updates": [
    {
      "site_id": 1,
      "site_url": "https://site1.example.com",
      "site_name": "Site 1",
      "type": "plugin",
      "slug": "akismet/akismet.php",
      "name": "Akismet Anti-spam",
      "current_version": "5.3",
      "new_version": "5.3.1"
    }
  ],
  "summary": {
    "core": 2,
    "plugins": 15,
    "themes": 3,
    "translations": 5,
    "total": 25
  },
  "page": 1,
  "per_page": 50,
  "total": 25
}
```

## mainwp/run-updates-v1

Execute updates on sites. Operations affecting more than 200 sites are queued for background processing.

**Method:** POST

```bash
# Preview a specific plugin update on selected sites
curl -X POST -u 'admin:xxxx' \
  -H 'Content-Type: application/json' \
  -d '{"input":{"site_ids_or_domains":[1,2,3],"types":["plugins"],"specific_items":["akismet/akismet.php"],"dry_run":true}}' \
  'https://your-dashboard.com/wp-json/wp-abilities/v1/abilities/mainwp/run-updates-v1/run'

# Apply the same selection after reviewing the preview
curl -X POST -u 'admin:xxxx' \
  -H 'Content-Type: application/json' \
  -d '{"input":{"site_ids_or_domains":[1,2,3],"types":["plugins"],"specific_items":["akismet/akismet.php"],"confirm":true}}' \
  'https://your-dashboard.com/wp-json/wp-abilities/v1/abilities/mainwp/run-updates-v1/run'
```

**Input Parameters:**

| Name | Type | Required | Default | Description |
|------|------|----------|---------|-------------|
| `site_ids_or_domains` | array | No | [] | Sites to update. Empty = all with updates |
| `types` | array | No | [] | Update types: `core`, `plugins`, `themes`, `translations` |
| `specific_items` | array | No | [] | Specific slugs to update |
| `dry_run` | boolean | For preview | false | Set true to preview; do not combine with confirm |
| `confirm` | boolean | For execution | false | Set true to execute after reviewing a preview |

Run a preview first with `dry_run: true`. The commands above show confirmed execution unless labeled as a preview.

**Response:**

```json
{
  "dry_run": false,
  "updated": [
    {
      "site_id": 1,
      "site_url": "https://site1.example.com",
      "site_name": "Site 1",
      "type": "plugin",
      "slug": "akismet/akismet.php",
      "name": "Akismet",
      "old_version": "5.3",
      "new_version": "5.3.1"
    }
  ],
  "errors": [],
  "summary": {
    "total_updated": 1,
    "total_errors": 0,
    "sites_updated": 1,
    "total_skipped": 0
  },
  "skipped": []
}
```

## mainwp/set-ignored-updates-v1

Add an item to a site's ignored updates list. In 6.3, use `action: ignore` here and [unignore-site-updates-v1](#mainwp-unignore-site-updates-v1) to remove a hold.

**Method:** POST

```bash
# Ignore a plugin update
curl -X POST -u 'admin:xxxx' \
  -H 'Content-Type: application/json' \
  -d '{"input":{"action":"ignore","site_id_or_domain":1,"type":"plugin","slug":"woocommerce/woocommerce.php"}}' \
  'https://your-dashboard.com/wp-json/wp-abilities/v1/abilities/mainwp/set-ignored-updates-v1/run'

```

**Input Parameters:**

| Name | Type | Required | Default | Description |
|------|------|----------|---------|-------------|
| `action` | string | Yes | - | Use `ignore`; `unignore` is rejected in 6.3 |
| `site_id_or_domain` | integer\|string | Yes | — | Site ID or domain |
| `type` | string | Yes | — | `core`, `plugin`, or `theme` |
| `slug` | string | Yes | — | Item slug (use `wordpress` for core) |

**Response:**

```json
{
  "success": true,
  "action": "ignore",
  "site_id": 1,
  "type": "plugin",
  "slug": "woocommerce/woocommerce.php"
}
```

## mainwp/unignore-site-updates-v1

Preview or remove one site's own update holds. Removing a hold can make an update eligible for later update runs, including queued runs; this ability does not install the update.

**Method:** POST

```bash
# Preview removal of one plugin's site hold
curl -X POST -u 'admin:xxxx' \
  -H 'Content-Type: application/json' \
  -d '{"input":{"site_id_or_domain":1,"type":"plugin","slugs":["akismet/akismet.php"],"dry_run":true}}' \
  'https://your-dashboard.com/wp-json/wp-abilities/v1/abilities/mainwp/unignore-site-updates-v1/run'

# Remove that hold after reviewing the preview
curl -X POST -u 'admin:xxxx' \
  -H 'Content-Type: application/json' \
  -d '{"input":{"site_id_or_domain":1,"type":"plugin","slugs":["akismet/akismet.php"],"confirm":true}}' \
  'https://your-dashboard.com/wp-json/wp-abilities/v1/abilities/mainwp/unignore-site-updates-v1/run'
```

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `site_id_or_domain` | integer or string | Yes | Authorized site ID or domain |
| `type` | string | Yes | `core`, `plugin`, or `theme` |
| `slugs` | array of strings | For plugin and theme | Nonempty list of item slugs; ignored for core |
| `dry_run` | boolean | For preview | Set to `true` to inspect the holds without changing them |
| `confirm` | boolean | For execution | Set to `true` to remove the site's own holds |

A preview returns `would_affect.holds`, a count, warnings, and errors. A hold's `still_held_by` field identifies a global or whole-site hold that will remain in effect. Execution returns `removed`, `not_held`, and `count` with `dry_run: false`:

```json
{
  "dry_run": false,
  "removed": [
    "akismet/akismet.php"
  ],
  "not_held": [],
  "count": 1
}
```

Global holds and whole-site ignore flags remain unchanged. Site access and **Ignore/Unignore Updates** permissions apply.
