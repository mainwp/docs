<Note>
These abilities require the Jetpack Protect Integration release that includes Abilities API support. Earlier builds do not register them. Check ability discovery on your Dashboard before using these examples.
</Note>

The Abilities-enabled Jetpack Protect Integration registers two read-only abilities in the `mainwp-jetpack-protect` category. Both use the `mainwp/` namespace on your MainWP Dashboard.

Both abilities read data the add-on already saved during earlier syncs. They do not start scans, sync sites, change settings, or contact child sites. To get newer results, synchronize your sites from the [Jetpack Protect page](/add-ons/security/jetpack-protect-extension) first.

## What You'll Learn

- List stored Jetpack Protect connection flags and vulnerability counts for your sites
- Read the latest stored scan and its vulnerability summaries for one site
- Understand what the responses leave out and why

## Prerequisites

- WordPress 6.9 or later on the MainWP Dashboard site
- MainWP Dashboard with Abilities API support; use version 6.2 or later for the `input_json` examples below
- The Abilities-enabled Jetpack Protect Integration, active on MainWP Dashboard
- An authenticated WordPress user with `manage_options` and access to the Jetpack Protect add-on
- Dashboard access to the target site for site-specific calls

Use an [Application Password](/api-reference/rest-api/application-passwords) or the [authentication methods in the Abilities API overview](/api-reference/abilities-api/overview#authentication). The examples use an Application Password.

These abilities are limited to administrators. Users without `manage_options` are refused even when Team Control would otherwise grant access to the add-on.

## Available Abilities

| Ability | Method | Purpose |
|---------|--------|---------|
| `mainwp/list-jetpack-protect-sites-v1` | GET | List stored connection flags, last scan time, and vulnerability counts for accessible sites |
| `mainwp/get-jetpack-protect-site-scan-v1` | GET | Read one site's latest stored scan with up to 100 vulnerability summaries |

Discover the abilities and their schemas:

```bash
curl -u 'USERNAME:APPLICATION_PASSWORD' \
  'https://your-dashboard.com/wp-json/wp-abilities/v1/abilities?category=mainwp-jetpack-protect'
```

Both abilities are annotated `readonly: true`, `destructive: false`, and `idempotent: true`.

## Request Rules

- `site_id` is a positive MainWP site ID such as `1`. Find IDs with the [Sites abilities](/api-reference/abilities-api/sites).
- Inputs reject extra properties.
- Times are ISO 8601 UTC strings, such as `2026-10-28T23:46:53Z`. A time is `null` when no scan time is stored.
- Both abilities return the same six `counts` fields: `total`, `core`, `plugins`, `themes`, `files`, and `database`.

## List Jetpack Protect Sites

**Ability:** `mainwp/list-jetpack-protect-sites-v1`<br />
**Method:** GET<br />
**Input:** `site_id`, `page`, and `per_page` (all optional)

| Input | Type | Default | Description |
|-------|------|---------|-------------|
| `site_id` | integer | None | Return only this site |
| `page` | integer | `1` | Page number, starting at 1 |
| `per_page` | integer | `20` | Sites per page, from 1 to 100 |

List all accessible sites:

```bash
curl -u 'USERNAME:APPLICATION_PASSWORD' \
  'https://your-dashboard.com/wp-json/wp-abilities/v1/abilities/mainwp/list-jetpack-protect-sites-v1/run'
```

Request a specific page:

```bash
curl -G -u 'USERNAME:APPLICATION_PASSWORD' \
  --data-urlencode 'input_json={"page":2,"per_page":50}' \
  'https://your-dashboard.com/wp-json/wp-abilities/v1/abilities/mainwp/list-jetpack-protect-sites-v1/run'
```

**Example response:**

```json
{
  "sites": [
    {
      "site_id": 1,
      "site_name": "Client Store",
      "connected": true,
      "scan_active": false,
      "plugin_hidden": false,
      "last_scan_at": "2026-10-28T23:46:53Z",
      "counts": {
        "total": 3,
        "core": 0,
        "plugins": 2,
        "themes": 1,
        "files": 0,
        "database": 0
      }
    }
  ],
  "page": 1,
  "per_page": 20,
  "total": 1
}
```

| Site field | Meaning |
|------------|---------|
| `site_id` | MainWP site ID |
| `site_name` | Site name from MainWP Dashboard |
| `connected` | `true` when the site's stored Jetpack connection flag is set |
| `scan_active` | `true` when the site's stored scan-active flag is set |
| `plugin_hidden` | `true` when the Jetpack Protect plugin is hidden on the child site |
| `last_scan_at` | Time of the last stored scan, or `null` |
| `counts` | Stored vulnerability counts by type |

The list includes only sites you can access that have stored Jetpack Protect data. `total` is the number of those sites. Increase `page` until you have read `total` sites. A page beyond the last result returns an empty `sites` array.

## Get a Site's Latest Scan

**Ability:** `mainwp/get-jetpack-protect-site-scan-v1`<br />
**Method:** GET<br />
**Input:** `site_id` (required)

```bash
curl -G -u 'USERNAME:APPLICATION_PASSWORD' \
  --data-urlencode 'input_json={"site_id":1}' \
  'https://your-dashboard.com/wp-json/wp-abilities/v1/abilities/mainwp/get-jetpack-protect-site-scan-v1/run'
```

**Example response:**

```json
{
  "scanned_at": "2026-10-28T23:46:53Z",
  "counts": {
    "total": 2,
    "core": 0,
    "plugins": 1,
    "themes": 0,
    "files": 1,
    "database": 0
  },
  "vulnerabilities": [
    {
      "type": "plugin",
      "affected_item": "Example Forms",
      "installed_version": "2.1.0",
      "fixed_in": "2.1.4",
      "title": "Example Forms <= 2.1.3 - Cross-Site Scripting",
      "severity": "medium"
    },
    {
      "type": "file",
      "affected_item": "suspicious.php",
      "installed_version": "",
      "fixed_in": "",
      "title": "Malicious code found in file",
      "severity": "critical"
    }
  ],
  "truncated": false
}
```

| Vulnerability field | Meaning |
|---------------------|---------|
| `type` | `core`, `plugin`, `theme`, `file`, or `database` |
| `affected_item` | Name of the affected component. For file threats, only the file name is returned, not its path. |
| `installed_version` | Installed version of the affected component, or an empty string |
| `fixed_in` | Version that fixes the issue, or an empty string when unknown |
| `title` | Threat title reported by Jetpack Protect |
| `severity` | Severity reported by Jetpack Protect |

The response includes at most 100 vulnerability summaries. When more findings are stored, `truncated` is `true`. `counts` still reports the full stored totals, so use the [Jetpack Protect page](/add-ons/security/jetpack-protect-extension) to review the complete list.

If the site has no stored scan, the response returns `scanned_at: null`, zero counts, an empty `vulnerabilities` array, and `truncated: false`.

## Privacy and Redaction

Both abilities return an explicit set of fields. They never return raw stored scan data, Jetpack account details, credentials, source URLs, or server file paths.

Before returning a response, the add-on checks every text value:

- Query strings and fragments are removed from URL-like text.
- Text containing a `Basic` or `Bearer` authentication marker is replaced with `[redacted]`. This also applies to site names and component names that contain these words followed by more text, such as `Basic Auth`.
- Common API keys, JWTs, PEM blocks, and `password=`, `token:`, or similar assignments are replaced with `[redacted]`.
- Text containing links, slashes, or `@` is returned as an empty string.
- Text values are limited to 200 characters.

This is a bounded masking policy, not a guarantee that any arbitrary string is safe to share.

## Error Handling

Standard authentication, schema, and method errors follow the [Abilities API error reference](/api-reference/abilities-api/overview#error-reference). The Jetpack Protect abilities return:

| Code | HTTP | Meaning |
|------|------|---------|
| `mainwp_permission_denied` | 401 or 403 | The request is unauthenticated, or the user lacks `manage_options` or access to the Jetpack Protect add-on |
| `mainwp_site_not_found` | 404 | The site ID does not exist or you cannot access it |
| `mainwp_jetpack_protect_read_failed` | 500 | The Dashboard could not read stored Jetpack Protect results. The error does not include database details. |
