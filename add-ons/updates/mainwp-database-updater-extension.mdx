Database Updater lets you find and start WooCommerce, Elementor, and Elementor Pro database updates from your MainWP Dashboard. Use it when these plugins need to update their stored data across your client sites. You can start the updates without opening each site's WordPress admin area.

A plugin's database holds the data it saves on a site. A database update changes how that data is stored or used. It is separate from installing a new plugin version.

## What You'll Learn

- Install Database Updater
- Check for database updates across your sites
- Update one site or all sites listed for a plugin
- Use a connected tool to check, preview, and approve updates

## Install Database Updater

<Steps>
<Step title="Open Manage Add-ons">
In your MainWP Dashboard, go to **Add-ons > Manage Add-ons**.
</Step>
<Step title="Choose Database Updater">
Click **Install Add-ons**. Find and select **Database Updater**.
</Step>
<Step title="Install and activate">
Click **Install Selected Add-ons**. When installation finishes, click **Activate Add-ons**.
</Step>
</Steps>

## Find Sites That Need an Update

Open **Sites > Updates > Database**. You can also select **Add-ons > Database Updater** to open the same view.

The list uses information saved during a site sync. A **sync** asks MainWP Child for the site's latest information and saves it in your Dashboard. Sync your sites to refresh the list before deciding what to update.

## Start a Database Update

<Warning>
Database updates change site data. Check that you have a usable backup before you start.
</Warning>

### Update all listed sites for one plugin

<Steps>
<Step title="Open the database update list">
Go to **Sites > Updates > Database**.
</Step>
<Step title="Choose the plugin">
Click **Update All** for the plugin you want to update.
</Step>
</Steps>

### Update one site

<Steps>
<Step title="Open the database update list">
Go to **Sites > Updates > Database**.
</Step>
<Step title="Find the site">
Expand the plugin row and find the site in the table.
</Step>
<Step title="Start its update">
Click **Update Now** next to the site.
</Step>
</Steps>

## Check the Status After an Update

An accepted request stays pending until the next site sync refreshes the saved status. Acceptance means the site accepted the work. It does not confirm the database update finished.

WooCommerce runs database update work in the background. Allow time for the plugin to process the update, then sync the site again. A sync refreshes the reported status. It does not prove every update step succeeded. If the update stays pending or the result is unclear, check the plugin's status and logs on that site.

MainWP remembers requests for the same site, plugin, and target database version. The target version is the database version the plugin wants to reach. Repeating an accepted request does not send the same update again. An uncertain request is also blocked from sending again because work may already have started. Waiting or syncing does not reset that protection.

## Use a Connected Tool

Database Updater 5.2.0 adds three **abilities**, named actions a connected tool can use. They let you check saved database updates, preview your selection, and run an update after you confirm. Each request covers one site and supports WooCommerce, Elementor, and Elementor Pro.

For example, ask your tool to check a client's site for database updates. Review a preview of the plugins you want to update. Check your backup before approving the update.

All three actions need administrator-level rights. You also need access to Database Updater, permission to update plugins, and access to the selected site. **Team Control staff without administrator-level rights are blocked**, even if they can access the site. These limits also apply to checks and previews.

The actions do not create or verify a backup. They also include saved updates for sites or plugins you have ignored in the Dashboard. Review your ignored-update choices before approving work.

See [Database Updater Abilities](/api-reference/abilities-api/database-updater) for the full steps and examples.

## Reference

For connected tools, all three abilities require the WordPress `manage_options` permission. This allows administration of site settings. Access to Database Updater, the `update_plugins` operation, and the exact site are also checked. Team Control restrictions still apply to accounts with administrator-level rights.

The [Database Updater abilities reference](/api-reference/abilities-api/database-updater#reference) lists the exact action names, request fields, results, and routes for connecting a tool.
