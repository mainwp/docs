The Database Updater Extension detects available database updates for WooCommerce, Elementor, and Elementor Pro. This means that you no longer need to access the WordPress admin area of a child site to start these database updates.

## How to Update the Databases

After you've installed the extension, a Database Updates tab becomes available. Open it from **Sites > Updates > Database**. You can also select **Add-ons > Database Updater**, which routes to the same view.

### Update databases on all child sites

<Steps>
<Step title="Go to Sites > Updates > Database">
</Step>
<Step title="Click Update All for the plugin you want to update">
</Step>
</Steps>


### Update databases on individual child sites

<Steps>
<Step title="Go to Sites > Updates > Database">
</Step>
<Step title="Expand the plugin row and locate the desired site in the table">
</Step>
<Step title="Click the Update Now button next to the desired site">
</Step>
</Steps>

### Check the update result

After you click **Update Now** or **Update All**, each site row shows one of these icons:

| Icon | Meaning |
|------|---------|
| Green check | The child site reported the database update as successful |
| Yellow clock | The child site started or queued the update. Hover over it to see "Update started; sync the site to verify completion." |
| Red X | The update failed or the extension refused it |

A database update stays listed as pending until the next site sync refreshes its status. After a yellow clock, sync the site to confirm the update finished. If any site shows a yellow clock or a red X during **Update All**, the progress modal stays open so you can review the results.

If the extension refuses the update, a red X replaces the row's buttons. Hover over the red X to see the reason.

When the last request for that update was sent to the child site but never confirmed, the tooltip reads: "This update was sent but never confirmed. Reload the page, then use Clear Stuck Request to try again." Before you clear the request, check the plugin on the child site to confirm its database update did not already run.

### Clear a stuck update request

The extension records each database update request it sends to a child site. This record stops the Dashboard from sending the same update twice. If a request times out or hits a connection error, the Dashboard can't confirm whether the child site ran the update. The request then stays pending, and **Update Now** returns the message "This update was sent but never confirmed. Reload the page, then use Clear Stuck Request to try again."

Before you clear a stuck request, check the plugin on the child site. Confirm that its database update did not already run.

<Steps>
<Step title="Go to Sites > Updates > Database">
If you just ran **Update Now**, reload the page. The **Clear Stuck Request** button appears only when the page loads.
</Step>
<Step title="Expand the plugin row and locate the site">
</Step>
<Step title="Click the Clear Stuck Request button next to Update Now">
</Step>
<Step title="Confirm the prompt">
The extension removes the stuck request, and the button disappears. Click **Update Now** to send the update again.
</Step>
</Steps>

<Note>
**Clear Stuck Request** appears only for requests that are still waiting for confirmation. You can't clear a request that the child site accepted or declined. To clear a request, you need the same permissions as **Update Now**: access to the Database Updater extension, the `update_plugins` capability, and access to the site.
</Note>

The extension never clears stuck requests on its own. It removes records of confirmed requests 30 days after they finish, using a daily scheduled task. When you uninstall the extension, it deletes all of its request records.

## MainWP Abilities

Database Updater 5.2.0 adds three abilities to read stored database updates for one site, preview a selection, and dispatch a confirmed update. Observations use the last stored sync data and do not apply the Dashboard's ignored-update settings.

Verify a fresh backup before dispatching. Acceptance means MainWP Child started or queued the update; sync later and check the plugin to confirm completion. The abilities share the Dashboard's request records and stuck-request protection.

Every call checks Dashboard Abilities API access, Database Updater access, the `update_plugins` right, and access to the selected site. See [Database Updater Abilities](/api-reference/abilities-api/database-updater) for authentication, previews, request examples, and results.
