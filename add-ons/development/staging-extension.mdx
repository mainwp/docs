**Staging Sites** are sites that duplicate your **Production Sites** _(same hardware, same software, same settings)_ so that any change can be tested and evaluated before being placed into production.
In other words, it's a complete but independent copy of your production site, including the database.
The MainWP Staging Extension allows you to create and manage staging sites without hassle.
The MainWP Staging Extension integrates with [WP Staging Free](https://wordpress.org/plugins/wp-staging/) and WP Staging Pro for creating, updating, and deleting staging sites. Publishing staging changes to production is handled separately through WP Staging; see [Push Staging Changes to Production](#push-staging-changes-to-production).

## How it works

Once you trigger the process of creating a staging site, the WP Staging plugin will duplicate all site files and copy them to a subdirectory.
All database tables will be duplicated, but the prefix will be changed.
Once this process is done, the necessary data will be updated in the **wp-config.php** file in the staging site.
Within a couple of seconds, you will have a replica of your child site where you can test updates.

After creating a staging site, MainWP adds the new staging URL to your MainWP Dashboard as a staging site and places it in the **Staging Sites** tag when that tag exists.
MainWP Staging Extension is extensively tested by the MainWP team. If you find any issues, please contact [MainWP Support](https://mainwp.com/mainwp-support/).

## Push Staging Changes to Production

The MainWP Staging Add-on does not provide a push-to-production action, including when WP Staging Pro is installed. Publishing takes place in WP Staging on the **production Child Site**.

WP Staging Free does not include the built-in push feature. To use it, install WP Staging Pro with a plan that includes **Push to Live**. Check [WP STAGING's current plan comparison](https://wp-staging.com/pro-features/) for availability.

These steps apply to a staging copy listed in WP Staging on the production site. Create and verify a fresh production backup before starting.

<Steps>
<Step title="Open the production site's WordPress admin">
You can also go to **MainWP > Add-ons > Administrative > Staging** (`/wp-admin/admin.php?page=Extensions-Mainwp-Staging-Extension`) and choose **Go to WP Staging** from the production site's action menu.
</Step>
<Step title="Select the staging copy in WP Staging">
Open **WP STAGING > Start / STAGING**, locate the staging copy, and select **Push Changes**.
</Step>
<Step title="Review what will be published">
Choose the files and database tables to copy. Selected tables replace their production counterparts, so protect any newer live orders, comments, or other content.
</Step>
<Step title="Start the push and verify production">
Confirm the selection, start the push, and check the live site when it finishes. Follow [WP STAGING's illustrated push guide](https://wp-staging.com/docs/copy-staging-site-to-live-site/) for the full procedure.
</Step>
</Steps>

<Note>
If the staging copy is on a separate server or was created with another tool, the standard push workflow may not apply. Review [WP STAGING's migration guidance](https://wp-staging.com/docs/category/migration/) for that setup. Connecting both sites to MainWP does not create a publishing connection between them.
</Note>
